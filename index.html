角色

管理員模式測試用，只作用在玩家身上，電腦不受影響。關掉這個面板就恢復正常規則。

被動技能平衡

估算基準（以 1 對 1 計）：一場約 6 個自己的回合，每人大約承受 100 點傷害、打出 100 點傷害。每個被動換算成「一場多賺多少血量」，都抓在 20～25 點左右，風格不同但總值接近。數值都可以再調。

改成線上對戰要怎麼做

這類遊戲是回合制，所以連線比即時動作遊戲簡單很多：玩家只送「指令」（移動、用道具、角度、力道），伺服器用同一套物理算出結果再廣播給房間裡每個人。原型的物理已經用固定時間步長和種子亂數寫，搬到伺服器可以直接共用。

伺服器權威

傷害、道具效果、地形破壞、誰落海都由伺服器算。用戶端改程式也改不了血量或道具數量，計時也以伺服器為準。

決定性物理

固定步長 1/120 秒、同一個亂數種子，兩邊算出的拋物線完全一樣，只需傳指令就能重播，流量很小。

技術選型

伺服器用 Node.js 搭 Socket.IO 或 Colyseus（內建房間與狀態同步）；前端可沿用原生 Canvas，之後要更多特效再換 Phaser。

房間流程

大廳 → 開房或快速配對 → 選角色、帶道具（有格數上限） → 對戰 → 結算經驗與金幣。斷線時保留座位 30 秒。

開發順序

  1. 階段 1單機原型：道具、跳躍挖地、手感與平衡（就是上面這個）
  2. 階段 2兩人房間連線：WebSocket、回合同步、斷線重連
  3. 階段 3帳號、等級、金幣、道具商店與角色造型
  4. 階段 42v2、4v4 團隊戰、角色專屬技能、更多地圖、排行榜

連線協定設計（房主權威）

大廳目前用 MockNet 假裝有朋友加入，介面和真連線用同一組呼叫：create / join / send / on。接上真連線時只換掉這一層。

  1. 房間房主建立房間拿到代碼（例：鳳梨8432），朋友輸入代碼加入，最多 8 人、魔王關 4 人。
  2. 大廳訊息pick 選角 · ready 準備 · team 換隊 · mode / map 房主設定 · addcpu / kick 補電腦踢人 · emote 表情 · start 開始。
  3. 開局房主送 seed、地圖、座位順序；每台用同一個 seed 生成地形，所以地圖一模一樣。
  4. 回合只有輪到的人能送指令：move、jump、dig、item、fire(角度, 力道, 武器)。房主驗證後廣播。
  5. 結算每台各自跑固定步長物理；房主在回合結束廣播 HP / 位置快照校正，避免誤差累積。
  6. 斷線30 秒沒回來由電腦接手；房主斷線時，座位最前面的人接任房主。
